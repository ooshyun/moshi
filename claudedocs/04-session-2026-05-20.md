## 2. 이번 세션에서 새로 밝혀낸 핵심 통찰

이전 세션이 다루지 않았거나 명확하지 않았던 부분 중 코드로 확인한 것들:

### 2.1 K=17 입력은 시퀀스 길이가 아니라 임베딩 합산

```
   ❌ 오해: 17개 codebook이 시퀀스 17개 토큰으로 들어간다
   ✅ 사실: 17개 codebook이 각자 별개 임베딩 테이블로 매핑된 후
           element-wise로 SUM되어 한 시점당 한 벡터로 들어간다
           (lm.py:390-397)

   K=17은 attention 차원이 아님 → 시간 S만 attention 대상.
```

### 2.2 임베딩 테이블은 codebook 자리마다 17개 별개

```
   text_emb        : vocab=32001, dim=4096   (text)
   emb[0..7]       : vocab=2049,  dim=4096   (Moshi M0..M7)
   emb[8..15]      : vocab=2049,  dim=4096   (User U0..U7)

   같은 정수 ID(예: 412)라도 자리에 따라 완전히 다른 벡터로 매핑.
   M0(semantic)와 M7(acoustic)는 다른 의미.
   Moshi와 User도 다른 화자 → 다른 테이블.
```

### 2.3 Text는 Mimi를 거치지 않는다

```
   Audio 경로: Temporal → Depth → Mimi.decode → PCM → Opus → WebSocket \x01
   Text 경로:  Temporal → text_linear → WebSocket \x02
                                       ↓
                            동시에 Depth Transformer의 첫 step의 seed로 재사용
                            (Inner Monologue 메커니즘)
```

### 2.4 학습 시 17 input / 9 loss 비대칭

```
   ┌─────────────────────┬────────┬────────────┬──────┐
   │ Stream              │ Input  │ Predicted  │ Loss │
   ├─────────────────────┼────────┼────────────┼──────┤
   │ Text (1)            │   ✅   │     ✅     │  ✅  │
   │ Moshi audio (8)     │   ✅   │     ✅     │  ✅  │
   │ User audio (8)      │   ✅   │     ❌     │  ❌  │
   └─────────────────────┴────────┴────────────┴──────┘

   User audio는 조건(conditioning)으로만 작동.
   loss를 걸면 모델이 user를 흉내내서 self-talk으로 망가짐.
```

### 2.5 Mimi semantic codebook ≠ Inner Monologue text token

```
   둘 다 "semantic"이라 불리지만 완전히 다른 modality:

   Mimi M0/U0   : RVQ 첫 codebook, audio 정수 (vocab=2048)
                  WavLM distillation으로 의미적 audio token
                  Mimi.encode 출력의 일부

   Text token T : SentencePiece subword (vocab=32000)
                  실제 단어 representation
                  LM.text_linear가 직접 출력
```

### 2.6 K=8, bins=2048 (=11 bits)의 설계 근거 3제약

```
   ① 음성 품질      : ≥1 kbps 필요 (neural codec 한계선)
   ② Depth latency  : K번 AR step/frame → 200ms 예산 안에 들어와야
   ③ 학습 가능성    : bins 너무 크면 dead code, 작으면 표현력 부족

   교집합 = K=8, bins=2048 → 88 bits/frame × 12.5Hz = 1.1 kbps
```

### 2.7 RVQ ≠ Mimi (위치 관계)

```
   Mimi = SEANet enc + Transformer enc + Downsample
        + RVQ (← 양자화 단계 1개)
        + Upsample + Transformer dec + SEANet dec

   RVQ는 Mimi 안의 한 layer일 뿐. 신경망 4겹이 RVQ 위·아래로 감쌈.
```

### 2.8 RVQ는 표준 backprop이 아닌 3중 학습 신호

```
   ① STE (Straight-Through Estimator):
      quantized = x + (quantized - x).detach()
      → argmin은 미분 불가지만 gradient를 그대로 통과
      → 인코더는 표준 backprop으로 학습

   ② EMA (Exponential Moving Average):
      centroid 위치 update (gradient 아님!)
      → online k-means, decay=0.99
      → core_vq.py:322-335

   ③ Commitment Loss:
      L_commit = ||x - sg(quantized)||²
      → 인코더가 centroid 근처를 출력하게 강제

   + Dead code revival (5 step마다 점검 + 부활)
   + K-means 초기화 (첫 batch에서)
```

## 5. 미해결 / 향후 조사 항목

이번 세션에서 깊이 들어가지 못한 영역:

1. **`modules/transformer.py`의 RingKVCache 세부** — capacity 동적 관리, exec_mask 처리
2. **`modules/seanet.py`의 stride 4번 (ratios=[8,6,5,4])** — 왜 이 조합인가
3. **`conditioners/` 와 CFG** — Hibiki에서만 사용. Moshi 본체는 condition 없음.
4. **`tts.py`의 forced text injection** — Inner Monologue를 거꾸로 이용해 TTS 제어
5. **Multi-stream 학습 시 voice/speaker assignment 정확한 로직** — 논문 §5.3 이상의 세부
6. **MLX 백엔드의 구현 차이** — quantization 4bit, Apple Silicon 최적화
7. **Rust `lm_generate_multistream.rs:152-260`의 pad_mult, repetition_penalty** — 학습 외 추론 제어

## 6. 이번 세션의 의의

이전 세션([`0X-claude-sessions.md`](0X-claude-sessions.md))이 **개념적 정리**(neural codec, RVQ, streaming의 일반 원리)였다면,
이번 세션은 **Moshi 코드베이스에 대한 실증적 검증**:
- 추상적 설명 ↔ 구체적 파일/라인 매핑
- 가설("이렇게 작동할 것") ↔ 코드 증거
- 잘못된 직관(예: K=17이 시퀀스) ↔ 정확한 메커니즘(embedding sum)

→ **이전 세션 노트와 본 세션 노트는 보완 관계**:
  이전 노트로 "왜 이렇게 만들었는가"를 이해하고,
  본 노트로 "코드 어디서 어떻게 작동하는가"를 확인.
